## 并发改造的运行验证

状态:**待执行**

P0–P8 代码已全部落地,但一次都没跑起来过。按下列顺序验证,每步失败即停:

1. `uv sync --all-packages`(新增 redis / gunicorn 依赖)
2. `alembic upgrade head`,确认 0025 / 0026 单头、且在**有存量数据的库**上把旧数据正确归到 legacy 用户
3. `docker compose up -d`,确认 8 个服务健康,worker 副本能领任务
4. 注册两个用户,交叉访问对方的 note / session / jd,确认一律 404 —— 这是 P0 的实质验收
5. 跑一场完整面试,确认 202 + job_id、SSE 断线用 `after_seq` 续看、`llm_calls` 三条链路都有记录且余额按 `cost_cny` 递减
6. worker 副本 1 → N,确认吞吐近似线性提升
7. 强杀一个 worker 进程,确认其未 ack 的任务被其他副本接管完成,无丢失、无重复扣费
8. 多副本同时跑 embed worker,确认同一批 chunk 只 embedding 一次、只扣一次费
9. 确认 API 容器内不再有任何后台常驻任务
10. 队列灌到水位线以上,确认返回 503 + `Retry-After` 而非超时;上游连续 429 后确认熔断打开
11. `工作进程数 × (db_pool_size + db_max_overflow)` 不超过 PostgreSQL `max_connections`

`user_id` 过滤位置清单见交付报告,需逐条核对。
