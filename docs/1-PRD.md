## 1. 背景与机会

### 1.1 背景

2026 年的中文互联网求职市场呈现两极化:**岗位数量持续收缩,而岗位对候选人的"匹配精度"要求显著提高**。一份通用简历投递 100 家拿不到几次面试,已经成为开发者跳槽期的常态。

与此同时,LLM 应用工程化已经从 2024-2025 年的"套壳期"进入"工程深度比拼期"。Agent、RAG、评测、MCP 等概念在头部公司 JD 中出现频率显著上升,但**真正完整跑通这条工程链路的开源代表作仍然稀缺**。

JobCopilot 同时回应这两个机会:既是给求职者的实用工具,也是作者本人的工程能力代表作。

### 1.2 机会

- **用户侧**:跳槽期开发者愿意为"提升面试邀约率"付出注意力(甚至付费),但当前市面上的简历工具(超级简历、五百丁等)只解决"排版美化",未触及"内容与 JD 的匹配优化"这一核心。
- **作者侧**:一份能完整体现 LLM 应用工程化(Agent 编排 / RAG / 评测 / MCP / 多模型路由 / 成本工程)的开源项目,是当前求职市场上的稀缺简历资产。

### 1.3 项目目标(OKR 风格)

**O:成为 1-3 年跳槽开发者最信赖的 AI 求职助手**

- KR1:产品上线后 3 个月内,真实活跃用户数 ≥ 100,周留存率 ≥ 40%
- KR2:用户使用前后,投递简历的面试邀约率(自报)平均提升 ≥ 30%
- KR3:GitHub 仓库 ≥ 500 Star,真实用户 issue ≥ 50 条
- KR4:作者本人在求职期内通过该项目获得的面试邀约 ≥ 10 个

## 2. 目标用户

### 2.1 单一用户画像(P0)

**画像名称**:跳槽中的中级开发者(Job-Seeking Mid-level Developer)

| 属性 | 描述 |
|------|------|
| 工作年限 | 1-3 年(含实习经历) |
| 角色 | 后端 / 前端 / 全栈 / 算法工程师(Python / Java / Go / TS 为主) |
| 当前状态 | 在职考虑跳槽 或 主动离职寻找新机会 |
| 核心诉求 | 在 1-2 个月内拿到比当前更好的 offer |
| 痛点 | ① 不知道自己的简历到底为什么收不到回复;② 改简历主观、效率低;③ 投了再多家也不知道哪些值得花精力定制 |
| 技术接受度 | 重度使用 ChatGPT / Claude / Cursor,愿意尝试新 AI 工具 |
| 隐私敏感度 | 高(简历包含真实姓名/电话/薪资/在职公司) |

**显式不在 P0 范围**:应届生、5 年以上资深工程师、产品/设计/运营等非技术岗位。

### 2.2 Job-to-be-Done(JTBD)

> 当我**正在跳槽**时,我希望**有人帮我针对每一份目标 JD 给出客观的能力差距分析、并把简历改到尽可能匹配那份 JD**,这样我就能**把投递时间花在最值得投的岗位上,并提升每一次投递的回复率**。

## 3. 核心用户故事

每条用户故事格式:**作为 [角色],我希望 [行为],以便 [价值]**。验收标准用 Given-When-Then 表述。

### US-001:导入一份 JD

**作为**跳槽开发者,**我希望**把任何来源的 JD(粘贴文本 / PDF 文件 / 截图)交给 JobCopilot 后,系统能自动结构化关键信息,**以便**我无需手动填表也能开始后续分析。

**验收标准**:
- Given 用户粘贴一段不少于 200 字的 JD 文本,When 用户提交,Then 系统在 ≤ 10 秒内返回包含「公司、岗位、工作地点、薪资范围、硬性技能、软性技能、加分项、工作年限、学历」九个字段的结构化结果。
- Given 用户上传一张 JD 截图,When 系统处理,Then 同样返回结构化结果,且关键字段抽取准确率 ≥ 85%。
- Given 系统抽取失败或字段缺失,Then 用户可手动补全任一字段。

**优先级**:P0

### US-002:建立个人档案

**作为**跳槽开发者,**我希望**上传我的简历后系统自动构建我的"能力档案"(项目、技能、经历的多粒度索引),**以便**后续所有匹配与定制操作都基于这份档案,我无需重复填写。

**验收标准**:
- Given 用户上传 PDF 简历,When 系统处理,Then 在 ≤ 30 秒内提取出「基本信息、工作经历列表、项目经历列表、技能列表、教育背景」结构化档案。
- Given 系统提取完成,Then 档案以可编辑表单展示,用户可修改任意字段。
- Given 用户保存档案,Then 档案被向量化并写入个人 RAG 索引(项目级 / 技能级 / 经历级三层)。

**优先级**:P0

### US-003:查看 JD-档案匹配分析

**作为**跳槽开发者,**我希望**对任意一份已导入的 JD 立刻看到我的匹配度评分、能力优势、能力差距,**以便**判断这份 JD 是否值得投。

**验收标准**:
- Given JD 与个人档案均存在,When 用户在 JD 详情页点击「分析匹配」,Then 系统在 ≤ 15 秒内返回:① 0-100 的总匹配度评分;② 命中的硬性技能列表;③ 缺失的硬性技能列表;④ 一段 ≤ 300 字的差距分析与建议。
- Given 匹配结果产出,Then 用户可看到每条结论引用的简历来源(可追溯,反幻觉)。

**优先级**:P0

### US-004:一键生成定制简历

**作为**跳槽开发者,**我希望**针对一份 JD 一键生成"重点突出该 JD 所需能力"的定制简历,并能下载 PDF,**以便**我直接用这份简历投递。

**验收标准**:
- Given JD 与档案存在 + 已完成匹配分析,When 用户点击「生成定制简历」,Then 系统在 ≤ 30 秒内生成 markdown 与 PDF 双格式简历。
- Given 生成完成,Then 用户可在编辑器内修改任一段落,修改后可重新导出 PDF。
- Given 简历内容,Then **绝对不允许出现个人档案中不存在的事实**(由 Reviewer Agent 强约束)。

**优先级**:P0

### US-005:模拟一轮技术面试

**作为**跳槽开发者,**我希望**针对某份 JD 模拟一场技术面试,包含追问、压力测试和打分反馈,**以便**我在真实面试前练习。

**验收标准**:
- Given JD 与档案存在,When 用户启动面试模拟,Then 系统至少进行 5 轮对话,涵盖基础题/进阶题/系统设计/行为面试四类。
- Given 用户回答模糊或不完整,Then 系统会进行至少一次追问。
- Given 面试结束,Then 系统输出:① 总分 0-100;② 每题得分与点评;③ reference answer;④ 改进建议。

**优先级**:P1

### US-006:管理投递追踪

**作为**跳槽开发者,**我希望**在统一看板中管理所有投递的状态(已投递 / 沟通中 / 面试中 / Offer / 已拒),**以便**不漏掉任何机会。

**验收标准**:
- Given 用户已生成定制简历,When 用户点击「标记已投递」,Then 该 JD 进入「投递中」状态。
- Given 投递状态变更,Then 用户可填写备注、设置后续动作提醒。

**优先级**:P1

### US-007:本地一键部署

**作为**注重隐私的跳槽开发者,**我希望**能在自己的笔记本上一行 docker compose 启动 JobCopilot,**以便**我的简历数据完全不离开本地。

**验收标准**:
- Given 用户克隆仓库 + 配置 .env(填入阿里云百炼 API Key),When 执行 `docker compose up -d`,Then 在 ≤ 5 分钟内完成镜像拉取与启动,可通过 `http://localhost:3000` 访问。
- Given 用户使用本地部署,Then 简历、JD 等所有用户数据仅写入本地 Postgres,不上传任何第三方服务(除百炼 LLM API 调用本身)。

**优先级**:P0

## 5. 非功能需求(NFR)

### 5.1 性能

| 指标 | 目标 | 备注 |
|------|------|------|
| JD 解析端到端延迟(文本) | P95 ≤ 10s | 含 LLM 调用 |
| JD 解析端到端延迟(图片) | P95 ≤ 15s | 含多模态 LLM |
| 简历定制生成延迟 | P95 ≤ 30s | 含 RAG + 生成 + Reviewer |
| 匹配分析延迟 | P95 ≤ 15s | 单次 |
| 检索延迟(单用户档案) | P95 ≤ 100ms | pgvector HNSW |
| API 首字节延迟(SSE) | P95 ≤ 1.5s | 流式接口 |

### 5.2 成本

| 场景 | 单次成本上限 | 模型档 |
|------|-------------|--------|
| JD 解析(单次) | ¥0.05 | qwen3.6-flash |
| 个人档案解析(单次) | ¥0.30 | qwen3.6-flash |
| 匹配分析(单次) | ¥0.15 | qwen3.6-flash + plus |
| 简历定制(单次) | ¥0.40 | qwen3.6-plus(Cache) |
| 面试模拟(单场,10 轮) | ¥1.50 | qwen3.6-plus(Cache) |

> 成本估算说明:基于 Qwen3.6-Flash 输出 7.2 元/M、Cache 命中 0.12 元/M、Plus 估算 ~3 倍 Flash 的常规模式。Cache 命中率假设 70%(Premium)/ 40%(Cheap)。实际值在 M2 评测期 promptfoo 回归后修正,见 ADR-0003。

**整体目标**:日活用户的 LLM 平均成本 ≤ ¥1.50/天/用户(切到 Qwen 后上调,见 ADR-0003)。

### 5.3 隐私与安全

- **本地优先**:所有用户数据默认仅存储于本机 Postgres
- **API Key 自管**:用户自带阿里云百炼 API Key(`DASHSCOPE_API_KEY`),JobCopilot 不托管
- **PII 处理**:LLM 调用前对身份证号、手机号(非必要场景)做脱敏占位
- **数据导出**:用户可随时导出全量数据(JSON + 原始文件)
- **数据删除**:用户可一键清除所有本地数据,级联向量库

### 5.4 可用性

- 单用户单机模式,可用性目标:**用户在本地启动后能稳定使用**(不追求多 9)
- 所有 LLM 调用必须有超时与降级:百炼不可用时显示明确错误,不假装成功

### 5.5 可扩展性

- 当前用户规模假设:**单实例支持 10 个并发用户**
- 横向扩展能力:数据库连接池、LLM 调用速率限制、SSE 连接管理
- 不为"百万 DAU"预留容量

### 5.6 国际化

- v1 仅中文 UI 与中文 Prompt
- 数据模型预留 `locale` 字段,但不在 v1 实现切换

## 6. 成功指标

### 6.1 北极星指标(NSM)

> **用户使用 JobCopilot 投递的简历相比未使用前的面试邀约率提升百分比**

测量方式:用户在投递追踪看板回填「是否收到面试邀约」,系统对比该用户使用前自报的历史邀约率。

目标:**上线 3 个月后,有效样本(≥ 5 次投递的用户)平均提升 ≥ 30%**。

### 6.2 输入指标(短期 Proxy)

在还没有足够 NSM 数据时,用以下输入指标驱动迭代:

| 指标 | 定义 | 目标 |
|------|------|------|
| 端到端完成率 | 用户从「粘贴 JD」到「下载定制简历」的完成率 | ≥ 70% |
| JD 字段抽取准确率 | 评测集上的字段精确匹配率 | ≥ 90% |
| 简历定制无幻觉率 | Reviewer 抽查中 0 幻觉的简历占比 | ≥ 95% |
| 匹配分析有用性 | 用户对匹配分析的"有用"评分(👍/👎) | ≥ 80% 👍 |

### 6.3 工程指标

| 指标 | 目标 |
|------|------|
| LLM 平均成本 | ≤ ¥1.50/日/活跃用户 |
| 评测集回归 CI 时长 | ≤ 10 分钟 |
| 单元测试覆盖率 | ≥ 70% |
| 端到端关键路径 e2e 测试覆盖率 | 100% |

## 7. Out of Scope(明确不做)

为了在 16 周内交付一个完整能用的产品,以下功能**v1 显式不做**:

| 项 | 不做的原因 |
|----|-----------|
| 自动爬取拉勾/Boss/LinkedIn JD | 法律风险高,违反目标平台 ToS;改用智能粘贴 + 用户主动触发 |
| 应届生场景特化 | 用户画像差异大,RAG 与匹配策略需要重做,放 v2 |
| 5 年以上资深工程师场景 | 同上 |
| 产品/设计/运营岗位支持 | 简历结构与技能体系完全不同 |
| 多用户协作(团队/HR 视角) | 项目核心是个人工具,不是 ATS |
| 推荐系统(主动推荐 JD) | 需要 JD 数据池,与"用户主动喂数据"原则冲突 |
| 投递自动化(代投简历) | 法律与伦理风险,且用户体验上没人愿意把账号交出去 |
| 在线协作 / 多端同步 | 与"本地优先"架构冲突,放 v2 通过端到端加密同步实现 |
| 移动端 App | 求职场景主要在桌面 |
| 中文以外语言支持 | 国际化是 v2 议题 |

## 8. 假设与依赖

### 8.1 关键假设

- **A1**:阿里云百炼 Qwen3.6 系列在 16 周开发期内 API 稳定可用、价格不发生颠覆性变化
- **A2**:目标用户愿意自购百炼 API Key 并粘贴到本地 .env(初步用户调研需要在 Week 2 验证)
- **A3**:目标用户愿意上传自己的真实简历到本地 JobCopilot(隐私顾虑可由本地优先架构解决)
- **A4**:1-3 年开发者中,每周愿意花 ≥ 30 分钟使用一个求职工具

### 8.2 外部依赖

| 依赖 | 用途 | 失败影响 | 缓解 |
|------|------|---------|------|
| 阿里云百炼 API | 所有 LLM 调用 | 系统不可用 | 显示明确错误,引导用户检查 Key 与网络;ADR-0003 复审条件触发时回切 DeepSeek |
| MinerU(开源) | PDF 解析 | PDF 入库不可用 | 降级到纯文本粘贴 |
| pgvector / Postgres 16 | 向量与业务数据 | 系统不可用 | 内置健康检查 + 启动校验 |
